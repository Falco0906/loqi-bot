R2-A.1 — ACCESS MIGRATION DESIGN
Status: design only; no source/config/schema/client behavior change.

DECISION: ONE ACTIVE ACCESS BOUNDARY
Canonical owner: extend `services/identity/dependencies.py` with the legacy-web bearer bridge, and retain `services/workspace_context.py` as the sole selected-workspace/membership resolver. This is two focused existing modules, not two authorization systems: identity resolves actor/session; workspace resolves authorized tenancy from that actor.

OWNERSHIP
1. Authenticated user resolution — `services.identity.dependencies`
   Owns Authorization header parsing and canonical identity-session validation (`get_current_auth`, `get_current_user_id`). Existing implementation is already canonical for `/api/v1` routes.
2. Legacy web-session validation — `services.identity.dependencies`
   Add the existing main.py logic as an explicit `resolve_web_access(request)` operation: bearer may be an identity access session or a bound legacy web-session bearer; output is typed `(user_id, bearer_token)`. It owns canonical-session touch/revocation checks and must fail closed.
3. Redis/session binding — `services.web_session_binding` remains persistence lookup owner; `services.session_cache` remains cache owner; `identity.dependencies.resolve_web_access` is their only HTTP-facing consumer. Redis is not an identity owner.
4. Legacy `users` FK bridge — retain `services.supabase.ensure_legacy_user_bridge` as persistence owner; invoke it only from `resolve_web_access` after authenticated identity resolution. Its bounded verification cache moves with the access operation; no route may provision it directly.
5. Selected workspace/membership/role — `services.workspace_context`
   Retains `resolve_workspace_context`, membership lookup, organization/workspace validation, and `WorkspaceContext`.
6. Compatibility default — a small `resolve_legacy_workspace(request, user_id)` function belongs in `workspace_context.py`, beside `resolve_workspace_context`. It first performs strict selected resolution; only NoWorkspaceAvailable falls back to the existing owner-single-workspace lookup for legacy/fixture accounts. Ambiguous selection remains 409. This is the sole temporary compatibility boundary.

DEPENDENCY DIRECTION
Routes/Copilot -> identity.dependencies.resolve_web_access -> identity services/session cache/web_session_binding/supabase bridge
Routes/Copilot -> workspace_context.resolve_workspace_context or resolve_legacy_workspace -> Supabase memberships/workspaces
workspace_context MUST NOT import identity, main, or routes. identity.dependencies MUST NOT import main or workspace_context. Callers compose the two outputs explicitly.

MIGRATION SEQUENCE (NO PARALLEL ACTIVE PATH)
A. Add characterization tests for `resolve_web_access` and `resolve_legacy_workspace` using existing security/tenant fixtures.
B. Move implementations verbatim into the two existing owners; migrate all main.py call sites in the same patch via imported names.
C. Migrate Copilot to call `resolve_web_access` + strict `resolve_workspace_context`; it never uses legacy fallback unless invoking a preserved legacy route contract.
D. Migrate tests: patch `services.identity.dependencies.resolve_web_access` and `services.workspace_context.resolve_*`, not main helpers. Retain test token shim at the canonical operation boundary.
E. Delete `_resolve_session_context`, `_resolve_web_user_id`, `_workspace_owner`, `_workspace_owner_and_summary`, `_session_token_from_request`, `_workspace_id_from_request`, `_resolve_selected_workspace_context`, `_selected_workspace_id`, `_resolved_workspace_id_or_default`, `_web_session_binding`, `_cached_session_identity`, bridge cache/helper from main.py in the SAME patch. No delegating wrappers remain.

EXISTING FILES TO REUSE
KEEP/EXTEND: services/identity/dependencies.py; services/workspace_context.py; services/session_cache.py; services/web_session_binding.py; services/supabase.py.
DO NOT CREATE: generic access manager/context/util module; a second workspace repository; a second session cache.

CALLER MIGRATION
Replace each main.py legacy resolver call with imported canonical operation. Route groups (web session, Discovery/jobs, Campaign, Outbound, Inbox, workflows, Mission Control, providers) use the same identity operation. For routes needing workspace scope, resolve once per request and pass `WorkspaceContext.workspace_id` downward. Copilot uses strict selection so model/page context cannot select authority.

TEMPORARY COMPATIBILITY TO PRESERVE
• URL `{session_token}` stays in legacy paths but never authenticates; Authorization remains mandatory.
• Bearer can remain either identity access session or valid bound web-session token.
• Legacy/fixture accounts with no durable active membership retain owner-single-workspace fallback only through `resolve_legacy_workspace`.
• Anonymous bootstrap POST /api/web/session remains excluded from legacy-session middleware.

MAIN.PY AFTER R2-A
Keeps middleware invocation and route composition only. It no longer owns identity/session/workspace business logic, Redis binding cache, legacy-user bridge, selected-workspace policy, or access compatibility policy.

BLOCKING-CALL FINDINGS
• identity validation/session touch, bridge persistence, cached session identity, workspace membership resolution, and owner fallback use synchronous Supabase clients currently wrapped variably with `asyncio.to_thread`.
• Correct future boundary: repositories/services expose async-safe access methods; do not make this broad conversion in R2-A. Preserve existing to_thread behavior during extraction and add no direct synchronous DB call on an async route.

SAFETY CRITERIA
One access route per request: resolve_web_access -> optional strict/legacy workspace resolver. No caller imports main access helpers. No service imports main. Tests patch canonical owners. R1 auth/workspace/Copilot tests pass before old main paths are deleted.
